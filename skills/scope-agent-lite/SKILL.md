# Scope the agent (lite)

The get-started reversal point. progenitor runs a multi-document design pipeline; Theory runs one
conversation that produces a confirmed shape. The soul questions — invariants and ≥3 concrete
refusals — are mandatory even though the heavy machinery is dropped. The confirmed shape is the cheap
point of reversal: no `create_agent` and no upsert happen before the operator approves it.

## When to use

- After `grant-authoring-scope`, to shape a new agent (or reshape an existing one) before authoring.

## When NOT to use

- Before authoring scope is granted.
- When the operator's need clearly exceeds the on-ramp (pattern catalog, formal multi-document design,
  fleets, cross-agent audit, API/SDK agents) — name the graduation boundary and stop, rather than
  half-authoring a shape Theory cannot honor.

## Inputs

- A recorded authoring grant (`grant-authoring-scope`) naming the target `agent_id`.
- The operator, available to answer and approve.

## Procedure

1. **Purpose.** Surface it in one or two sentences — one agent, one subject. If the purpose is
   multi-subject or the agent is trying to be two agents, propose a split rather than authoring a muddle.
2. **Principal + hosts.** Surface the principal and authorization model (who directs the agent, what
   it may and may not do on their behalf), and name the TARGET HOST PROFILE(S) the namespace will render
   onto: `codex`, `claude_code`, `antigravity` — so `define-install-layout` knows which layouts to author.
3. **Invariants + refusals.** Name 3–7 INVARIANTS the agent's identity rests on, in plain language.
   Then draft a REFUSAL LIST of at least three CONCRETE refusals, each traceable to one named
   invariant, each phrased so the "let me bypass X just this once" framing would trip it. Refuse
   generic refusals ("be safe", "don't do bad things") — push for specificity. Speed must not erode
   refusal-list quality here.
4. **Detect graduation needs.** If the operator wants a reusable pattern catalog, the formal
   multi-document scope/patterns/design pipeline, cross-agent audit as a standing practice,
   fleet/multi-agent composition, or an API/SDK agent, name plainly that this exceeds the get-started
   on-ramp, point to graduating to a formal progenitor, and STOP.
5. **Read back + approve.** Summarize the confirmed shape inline (purpose / principal / hosts /
   invariants / refusals) and get explicit operator approval. This approval is the reversal point.

## Outputs

- A confirmed, operator-approved agent shape: purpose, principal + authorization, target host
  profiles, 3–7 invariants, and ≥3 concrete invariant-grounded refusals — enough to author soul-first.

## Red flags

- Vague purpose; a multi-purpose agent; refusals that are generic rather than invariant-grounded.
- "Just publish it, soul later" — the soul questions are not optional.
- Proceeding to author before the operator approves the read-back.
- Half-authoring a shape that actually needs formal-progenitor rigor.

## After completing

- Hand the confirmed shape to `author-soul`.
