# Onboard a TheoryCloud workload

Use for registry/control-plane planning before a workload is managed.

## Procedure

1. Identify workload: first-party platform app, customer workload, or customer-owned connected account.
2. Define application, environment, and account binding records.
3. Select account class policy.
4. Define deploy contract and preflight requirements.
5. Define action lease and approval requirements.
6. Define receipt/evidence expectations.
7. Identify claims allowed after onboarding.

## Output

```markdown
# Workload Onboarding Plan: <workload>

## Workload identity
## Account class
## Registry records
## Deploy contract
## Action/approval policy
## Receipt/evidence expectations
## Claims allowed / blocked
## Open blockers
```

Onboarding plans do not imply managed deployment proof.
